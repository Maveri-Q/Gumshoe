Why one sentence

A test that looks for a button by its code name breaks when the code changes. A bug hunt goes back through months of changes. “The menu closes” still means the same thing on an old version.

How it avoids wrong answers

Kane does the steps. A second Kane run only looks, and judges two opposite statements. A second reader judges the saved screen. All must agree, in two tries, or the commit is skipped. 21 of 153 tries were refused.

What it can't do yet

  • Old versions must still build. If one doesn't, that commit is skipped.
  • The report must say clearly what should happen. A vague report gives a vague check.
  • Kane can misread a screen, and so can the second reader. If both misread it the same way twice, the answer is wrong.
  • It names the commit where the behaviour changed. That is not always the real cause.
  • 6 reports from 2 apps is a small sample.
  • Each app needs a short build file, written once by a person.
