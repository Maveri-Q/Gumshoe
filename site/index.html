Which commit broke it?

Give Gumshoe a bug report. It turns the report into one sentence. Kane checks that sentence in a real browser on older versions of the app. About half the suspects go each time, until one commit is left.

Every bug we tried

3 of 3 hunts ended on one commit. Where the maintainers named a commit, Gumshoe named the same one in 3 of 3. All bugs are real and public. None were planted.

Why one sentence

A test that looks for a button by its code name breaks when the code changes. A bug hunt goes back through months of changes. “The menu closes” still means the same thing on an old version.

How it avoids wrong answers

Kane does the steps. A second Kane run only looks, and judges two opposite statements. A second reader judges the saved screen. All must agree, in two tries, or the commit is skipped. 4 of 57 tries were refused.

What it can't do yet

  • Old versions must still build. If one doesn't, that commit is skipped.
  • The report must say clearly what should happen. A vague report gives a vague check.
  • Kane can misread a screen, and so can the second reader. If both misread it the same way twice, the answer is wrong.
  • It names the commit where the behaviour changed. That is not always the real cause.
  • 3 bugs with a known answer is a small sample, from 2 apps.
  • Each app needs a short build file, written once by a person.
